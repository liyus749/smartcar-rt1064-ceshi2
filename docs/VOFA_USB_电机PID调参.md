# 核心板 Type-C 电机 PID 调参

本版用于**架空驱动轮调电机速度环**，不进行摄像头循迹。左右编码器、PWM、舵机引脚保持原映射。上电停车，舵机回中790；默认左右请求速度100，左右电机PID均为P=8.00、I=0.15、D=0。这里的PID与舵机PD是两套参数。

烧录 `project/mdk/Objects/rt1064_usb_motor_pid_vofa.axf`，这是独立调参归档；从源码重编译请选择 `main.c` 中的 `MOTOR_DIAGNOSTIC_MODE=3`，当前默认输出的模式以README顶部为准。

## 连接

1. 架空驱动轮，用车上电池给电机驱动供电。Type-C用于核心板USB通信。
2. 按原方法烧录并运行，再用数据线连接**核心板上的USB1 Type-C**和电脑。无需无线模块、杜邦线或改跳线。核心板说明书正文第9页确认此口直接连接MCU USB1；SWD下载器上的虚拟串口是另一条路径。
3. VOFA选择 **Serial / 串口**，端口选择插入核心板Type-C后新增的COM，不能沿用蓝牙或下载器端口。固件VID/PID为 `1FC9:0094`，设备通常显示USB串行设备。Windows10/11使用系统USB CDC驱动。
4. 选 **115200、8数据位、无校验、1停止位、无流控**。原生USB不受实际UART波特率限制，这里统一使用115200。
5. 协议选 **FireWater**，然后连接。停车也持续发送数据，无需自动发送握手命令。屏幕应显示 `USB: READY`。
6. 建议一组曲线画CH0～3，另一组画CH4～5，避免PWM量级掩盖速度曲线。

依据 [VOFA官方FireWater协议](https://www.vofa.plus/docs/learning/dataengines/firewater/)，输出为逗号分隔数字，真实换行结束。目标发送频率50Hz，屏幕10Hz；USB忙时跳过遥测，不阻塞电机控制。

## 通道表

VOFA通道从CH0开始；如果界面从1编号，下表编号加1。

| 通道 | 含义 |
| --- | --- |
| CH0、CH1 | 左、右轮实际闭环目标，包含软启动 |
| CH2、CH3 | 左、右编码器速度 |
| CH4、CH5 | 左、右电机PWM输出，0～4000 |
| CH6、CH7 | 左、右请求速度，停车也保留 |
| CH8、9、10 | 左电机P、I、D |
| CH11、12、13 | 右电机P、I、D |
| CH14 | 运行开关：0停、1运行 |
| CH15 | 停止原因码 |
| CH16 | 已接受命令累计数 |
| CH17 | 错误命令/接收溢出累计数 |

速度单位是**编码器计数/10ms**，不是RPM或cm/s。每10ms读取编码器，两个连续样本平均后供20ms闭环使用，CH2/3显示同一反馈。PWM满量程10000，输出上限4000对应40%。到4000仍无法跟上目标时，需要结合供电、机械负载判断，继续增大PID不能提高输出上限。

## 下发参数

VOFA发送框选择**文本/ASCII**，关闭HEX，开启追加换行（LF或CRLF）。命令用小写，每次一行。不要发送字面字符 `\n`，不要开启循环发送启动命令。

| 命令示例 | 功能 |
| --- | --- |
| `speed=100` | 同时设置两轮请求速度 |
| `speed=170` | 两轮请求速度设为170 |
| `left=100` | 仅设置左轮请求速度 |
| `right=120` | 仅设置右轮请求速度 |
| `pid=8,0.15,0` | 同时设置两轮电机P、I、D |
| `lpid=8,0.15,0` | 仅设置左电机P、I、D |
| `rpid=8,0.15,0` | 仅设置右电机P、I、D |
| `run=1` | 启动本轮测试，最多10秒 |
| `run=0` 或 `stop` | 停车并清零两轮输出 |
| `reset` | 停车，恢复请求100和PID 8/0.15/0 |

非零速度70～240；0表示该轮停转。1～69、负数、超过240、NaN/Inf或残缺命令均拒绝，不自动换成另一个速度。P、D范围0～100，I范围0～20。PID整条合法才生效。修改参数不会自行启动车轮。

例如依次发送 `speed=100`、`pid=8,0.15,0`、`run=1`，观察曲线；运行中可发送 `speed=130`。确认CH6/7和CH8～13变化，CH16递增表示收到了合法命令；CH17增加表示拒绝了输入。非零目标增加保留原来的软启动量级，降低目标立即应用，因此CH0/1会有斜坡，CH6/7是输入的请求。

参数保存在RAM，停车不丢，断电恢复默认。不会自动写Flash，也不会修改已有循迹归档的PID。

## 本测试版按键

- **C13**：启动/停止，每次启动最多10秒。
- **C12**：选择BOTH → LEFT → RIGHT，决定调速键作用的轮子。
- **C15**：所选速度减5；**C14**：加5，范围70～240；上电默认BOTH。
- 按住只动作一次，上电按住的键先松开再用。C13优先。

屏幕显示请求速度、实际目标、编码器、左右PWM、两侧PID、命令计数和停止码。

CH15停止原因：0手动停止/就绪；1本轮10秒结束；2左轮反馈持续过低；3右轮反馈持续过低；4两轮反馈持续过低；5USB丢失/总线重新枚举。上电未接USB时也可能显示5，连接后重新启动即可。

起步1.5秒后，任何请求非零的轮子连续0.5秒反馈小于3，会停止两轮。USB拔出或总线复位也会停车，重连不自动启动。关闭电脑软件但线仍连接不等同于拔线，可用C13/stop停车，本轮仍有10秒上限。

## 调参观察

先在速度100观察CH2/3是否跟随CH0/1。保持电机D=0，先调PI，每次只改变一项。速度慢慢爬升但长期低于目标，可小幅增加I；围绕目标反复波动时先降低I，再检查P。左右负载不同，可分别调。电机D会放大计数噪声，先把PI调好。

保存起步、100升130、130降100三段波形，记录左右P/I/D，再结合下地负载验证。架空调好不代表已经能稳定跑赛道。PID是20ms离散增量形式，不能直接照搬其他控制周期的参数。

原循迹版仍保留在 `project/mdk/Objects/rt1064_pd_keys_002_spd170.axf`：BIN二值图、舵机P/D按键步进0.02、基础速度170。要从源码恢复，把 `MOTOR_DIAGNOSTIC_MODE` 改为0后重新编译（当前也会启用新环岛；只跑原弯道十字时再设 `USE_ISLAND=0`）；调参得到的左右电机参数需要另行固定到源码。

## 验证范围

主机测试运行真实MotorTune和MotorPID代码，覆盖独立PID、零目标、采样平均、命令分包/越界、按键、超时、低反馈、USB断开及不同负载简化仿真。USB缓冲测试覆盖收包跨界/溢出/取消、异步DMA缓冲寿命、忙/错误返回和中断状态；另已回归循迹差速控制。软件验证与Keil编译不代表已经在车上完成USB枚举或调好实际PID，首次烧录后仍需确认新COM和实测波形。
