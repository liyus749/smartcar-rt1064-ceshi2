# 按文章实现的左右环岛入口三拐点判定

当前三拐点无线VOFA＋IPS200屏幕版本烧录 `project/mdk/Objects/rt1064_wireless_article_corners.axf`，默认 `rt1064.axf` 同版，启停和调参见[无线循迹说明](VOFA_无线循迹控制.md)。此前 `rt1064_wireless_3corners.axf`、带按键 `rt1064_roundabout_camera.axf` 和无线 `rt1064_wireless_4ch.axf` 归档保留各自原来的识别逻辑。当前配置为`MOTOR_DIAGNOSTIC_MODE=0`、`USE_ISLAND=1`、`USE_LEGACY_GYRO=0`，保留二值图、十字、弯道、舵机PD和电机闭环，不读取IMU660RA，也不把IMU660RC当成RA使用。下面按键操作只适用于旧归档，无线版使用`S1=%f!`启停、`P1=%f!`/`D1=%f!`调舵机，无需心跳。

入口判定按 [RoyZz_《智能车学习日记【四】——环岛》](https://blog.csdn.net/qq_53239103/article/details/126683046) 的下拐点突变、中拐点单调性反转、上拐点远端连续/近端突变思路，针对188×100图像独立实现于 `project/code/Roundabout.c/.h`。按用户明确的赛道条件，首次判定始终要求下拐点存在，不启用原文缺下拐点时的两点入口分支。入环后的白区路径规划、环内循线、出环引导及控制保护沿用本工程现有实现。

## 屏幕与按键

- **Isl**：环岛状态，见下表。
- **RD L / RD R / RD -**：左环、右环、无环岛。
- **F0**：正常；F1当前环岛/路径特征持续丢失；F2摄像头长时间不更新；F3运行中阶段超时。
- 青色间断点：本帧环岛引导边线；品红小十字：本帧实际观测的环岛角点。基础左右边线和中线保持原配色，原始二值图不被补线改写。
- C13启动/停车；C12选择舵机P/D；C15减、C14加，P/D步进仍为0.02。默认P=1.80、D=2.00；中位790、左870、右715。

上电停车，先原地看识别，再按C13试跑。停止时识别图仍更新，但不会仅因处理了许多静态帧就推进进出环阶段。故障时会停车；移回能看清入口的位置后按C13重试，等一帧新图像再恢复控制。

| Isl | 含义 | 处理 |
| --- | --- | --- |
| 0 | 普通赛道 | 原弯道/十字处理 |
| 1 | 三点确认、接近入口 | 依据完整外侧边线维持入口直行；下拐点接近第85行后进入2 |
| 2 | 等待入环 | 继续补入口缺失边线，检查当前岛心与角点位置 |
| 3 | 入环 | 重新扫描，生成通往当前入环特征的白区引导路径 |
| 4 | 环内 | 跟踪真实弯道边界，允许原有图像偏差差速辅助 |
| 5 | 出环 | 出口角点与白色支路连续确认后，引导出环 |
| 6 | 出环摆正 | 重新寻找当前可见白色通道并补线 |
| 7 | 恢复直道 | 真实近端双边稳定后退出，进入短暂防重复识别间隔 |
| 8 | 故障停车 | 显示F码，停止电机 |

基础直道速度仍是170。确认环岛后，**基础目标上限70**；这是内轮/直行基础目标，不是每轮速度都不得超过70。环内明显偏差满足原差速条件时，外轮最多提高60%，例如内70、外112。入环、出环和摆正期间撤掉差速，避免补线转向与额外差速叠加。

## 识别和补线

先对原始搜线结果检查十字；已确认环岛时，十字模块让出处理权。尚未确认环岛时，正在候选或活动的十字优先，不允许两套补线同时工作。

首次环岛判定先扫描与近端赛道连通的白区，按文章的三个入口角点分别查找：

1. **下拐点（原文红点）**：找入口近端赛道边线的突变处。其靠近车的一侧至少连续3行；向远处相邻行突变至少3像素，跨3行变化至少6像素，或突变后出现丢线。该点位于岛心下方的入口路肩，不把岛心黑区的下端当成下拐点。
2. **中拐点（原文橙点）**：找环岛侧边线朝车道内最突出的单调性反转点。两侧都要有可见轮廓和至少4像素的突出量，允许2像素抖动；拒绝孤立尖峰和反复折返。
3. **上拐点（原文绿点）**：找岛心上方远端赛道重新出现的边线。其远端至少连续3行，近端出现突变或丢线；与中拐点横坐标距离不超过24像素，避免匹配到其他路肩。该点不是岛心黑区的上端。
4. 要求 `下拐点行 > 中拐点行 > 上拐点行`，同时对侧边线有至少35个有效行，至少85%的有效行拟合残差小于4像素。三点方向、位置连续3个新帧稳定后，从状态0进入状态1。

**按用户要求，下拐点是首次判定的必要条件。** 即使近端大量丢线且找到中、上两点，也不直接判为环岛或跳到状态2。状态1改为依据仍可见的下拐点位置推进：到第85行附近并连续3帧确认后进入状态2，后续仍按当前可见几何证据进环。首次识别与状态推进都不凭旧角点补线。

右环岛镜像到左环岛坐标后使用同一判定。屏幕品红十字显示本帧实际入口角点，候选尚未确认时也显示，图像丢失立即清除旧点。普通弯道、十字、黑点及缺少任一入口拐点的形状不能独立确认环岛；首次识别不再依赖封闭黑色岛心或黑块面积。

接近时以完整外侧边界和此前路宽模型维持直行；入环时改变扫描方式，跟踪与近端白路连通的区域，避免原来的左/右标签失效。引导路径检查每行白色通路、横向连续性和边界余量，不接受直接穿过黑色岛心的斜线。找不到当前几何证据时，不继续沿用旧角点补线。

环内使用重新扫描得到的真实边界；只有一侧可见时，借助入环前路宽估算中线。环岛与十字期间冻结偏差模块的路宽学习，避免支路宽度或人工补线污染后续普通弯道。

出口先要求外边界已经恢复过，再寻找图像内部的真实下拐点和连续向外扩展的白色支路。平滑弯道单纯出画面、或黑色区域里的丢线，不作为出口。出口上角点不是必需条件，但实际引导仍必须落在本帧连通白区。只有成功引导过出口，才允许转入摆正阶段。

## 超时与恢复

只在运行中累积阶段超时，停车观察不消耗它。连续8帧缺少必要图像/路径证据、确认环岛后超过约500ms没有新图像、某阶段运行约15秒不推进或总过程约40秒不结束，会锁定故障停车。重连图像不会自行发车。C13重试先等待一帧新图像，再重新识别入口。

## 适用范围与实车检查

软件模拟通过不代表实际赛道已经跑通。首次确认不要求岛心封闭或与背景分离，但入口的下、中、上三个拐点必须同时可见；当前按用户提供的入口下拐点始终可见这一条件实现。若实际帧找不到下拐点，会清除候选计数并继续观察，不启动两点判定。阈值需要按实际二值图调整。

摄像头最近15～20cm、中间50～60cm、远处约130cm，并不能直接确定每个状态的准确行数。默认阈值需要结合实际入环、出环画面验证。先观察入口处Isl能否由0稳定进入1/2，RD方向是否正确，再看3能否进入4，最后看5→6→7→0。记录失败前后的Isl、RD、F和二值图，可区分未识别、阶段切换和引导路径失败。

主要参数集中在 `Roundabout.h`；入环位置和图像几何检查在 `Roundabout.c`。不要先放宽所有判定阈值，也不要通过加大舵机P掩盖状态识别错误。

## 验证与保留版本

测试运行真实LineDetect/Cross/Roundabout/Err代码，覆盖三个角点坐标的左右镜像、与背景相连的岛心、缺任一拐点与单行尖峰排除、角点跳变重计数、特征消失清除、三帧确认、静止观察、近入口三点识别、缺下拐点不走两点分支、入口红/橙/绿点定位、投影环道的七阶段与退出、普通弯道/十字/单侧开口/黑点排除、补线路径白区与边界约束、缺图和超时。另用生产20ms控制代码验证环岛基础限速、进出环撤销差速、环内差速、故障停车和等待新帧。已有十字、P/D按键、帧快照和USB电机调参检查保留。

USB电机调参归档仍是 `project/mdk/Objects/rt1064_usb_motor_pid_vofa.axf`，原弯道十字归档为 `project/mdk/Objects/rt1064_pd_keys_002_spd170.axf`。需要USB独立调电机时，烧录USB归档；从源码编译则选择 `MOTOR_DIAGNOSTIC_MODE=3`。仅关闭新环岛时设 `USE_ISLAND=0`，保留 `MOTOR_DIAGNOSTIC_MODE=0` 并重新编译。
