# SERVO TEST T2：H5/C30 独立舵机输出测试

用途：循迹时 Ang 变化而舵机不动，用两种输出方式缩小问题范围。Ang/PWM 都是程序指令，并非真实转角或针脚波形反馈。此测试尚需实车确认，编译或电脑模拟通过不代表硬件已经正常。

烧录文件：`project/mdk/Objects/servo_T2/rt1064_servo_T2.axf`。别名 `project/mdk/Objects/rt1064_servo_output_test.axf` 在本次编译后更新为相同固件。

独立 Keil 工程：`project/mdk/rt1064_servo_output_test.uvprojx`，目标 `nor_sdram_zf_dtcm`。入口为 `project/diagnostics/servo_output_test.c`，引用回退快照中的Servo.c与标定值；不会改动原循迹入口、参数或默认工程。输出目标为 `rt1064_servo_T2`，产物存到独立 `Objects/servo_T2/`。独立工程已复制当前主工程的CMSIS-DAP下载配置。

舵机仍接新板 H5/C30：白线信号C30，红线舵机电源，黑线GND。下载后断电重启，屏幕应显示 `SERVO TEST T2 / C30`；如果显示摄像头图或RUN-S1 R1，则仍是循迹固件。电机全程保持关闭；不初始化摄像头、无线、编码器、循迹定时器或按键，不需要发送 S1。上电后自动开始，观察两个阶段的实际动作：

| 屏幕阶段 | 输出路径 | 位置顺序 |
| --- | --- | --- |
| A: HARDWARE PWM | 实际生产 Servo.c 及原 FlexPWM 驱动 | 790 → 830 → 790 → 750 → 790 |
| B: GPIO / GPT2 | 同一 C30 改为 GPIO，用 GPT2 整段计时生成脉冲 | 790 → 830 → 790 → 750 → 790 |

每个阶段首次中位保持约3秒，其余位置分别约2秒。A和B组成一轮，自动重复三轮，屏幕显示ROUND 1/3、2/3、3/3，总共约70秒。完成后显示 `DONE: HOLD CENTER 790`，持续输出中位脉冲；断电重启可重复测试。屏幕DUTY/PULSE是输出指令，不是实际测量的转角或针脚波形。

50 Hz 对应 20 ms 周期，750/790/830 分别为 1500/1580/1660 μs 高电平，均在现有实测机械范围 715～870 内。GPIO 阶段直接使用 GPT2 的 24 MHz 晶振计时，避免旧 `system_delay_us()` 每微秒循环累积开销改变脉宽。屏幕阶段切换可能产生短暂帧间隔。

结果只用于缩小排查范围：

- A、B 都正常：当前简化输出链路能工作，继续对比循迹固件运行后的引脚复用、PWM 寄存器和烧录文件。
- A 不动、B 能动：重点检查 FlexPWM 初始化、装载、输出使能或信号时序。
- A 能动、B 不动：检查诊断 GPIO/GPT2 路径及实际波形，不能据此判断舵机损坏。
- A、B 都不动：继续实测核心板 C30 与 H5 信号脚的波形、线路和带载供电；此结果仍不能单独断定舵机损坏。

恢复跑赛道时烧录原 `project/mdk/Objects/rt1064_track_run.axf`，不要使用独立诊断固件跑车。

电脑模拟检查：`python tests/run_servo_output_test.py`，覆盖实际诊断入口和 Servo.c 的输出范围、三轮顺序及PWM/GPIO复用切换、GPIO高低脉冲时长和电机关闭。该检查不测量真实针脚。
